[bug · medium] `isLink` compares the entry's realpath against its literal (non-canonical) path. For
a genuine directory this only holds when every ancestor is already canonical; if the path contains a
symlinked ancestor (e.g. macOS `/var` → `/private/var`, or a symlinked project/home dir) or a
Windows 8.3 short name, `realpathSync(nmEntry)` differs from `nmEntry`, so a real entity directory
is misclassified as a link (`link-elsewhere`) instead of `entity`. The unit test NMC-1 (ws built
from `os.tmpdir()`) would exhibit exactly this on macOS. Compare against the canonical parent +
basename instead of the literal path so only a real reparse point/junction on the final component
counts as a link.

-   return normPath(realTarget) !== normPath(nmEntry)
+   // 与「父目录 canonical + 自身文件名」比较：仅当最终组件本身是链接时二者才不等，
+   // 避免路径含符号链接祖先/Windows 短名时把真实目录误判为链接
+   const expected = join(realpathSync(dirname(nmEntry)), basename(nmEntry))

─── src/commands/repair.ts:265-265 ───
[maintainability · low] `planOrphan` is invoked once per orphan file (inside `buildPlan`'s per-file
loop), and this is the only place that resolves the "original value" when no sibling declares a
non-local range. For a lib linked (localish) from two member directories with no sibling version,
`ternaryOriginal` is therefore called twice — the user is asked to pick the source / type the range
once per file, and the two files may end up with different originals. The spec models this as a
single per-lib decision (`ternaryOriginal` returns a Map keyed by all hits). Consider resolving the
original once per lib key (cache it for the remaining files of the same entry) so the whole lib gets
one consistent value and a single prompt.
